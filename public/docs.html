Plug-and-play DBC data for launchpads, terminals & agents

DBC Flow indexes every Meteora Dynamic Bonding Curve transaction on Solana mainnet in real time, decodes the program's emit_cpi events (EvtSwap2, EvtInitializePool, EvtCurveComplete, migration_damm_v2…), enriches them (token metadata, USD prices, market cap, curve progress) and serves them over SSE, WebSocket, REST, a zero-dependency TypeScript client and an MCP server for AI agents.

/api/pools?sort=progress /api/launchpads /api/events /api/stats

Why

Every team building on DBC re-implements the same plumbing: subscribe to the program, fetch transactions, decode Anchor CPI events, resolve configs and token metadata, compute bonding progress, detect graduations and migrations to DAMM v2. DBC Flow does it once, and exposes signals that are not directly on-chain:

  • Graduation progress & ETA — quote reserve vs. migration_quote_threshold on every swap, ETA from a 10-minute linear regression of progress.
  • Lifecycle stream — pool_created → near_graduation → graduated → migrated (DAMM v2 pool address).
  • Flow signals — 5m/1h volume, net buy flow, unique traders, sniper buys (within N s of launch), whale buys, dev buys/sells.
  • Launchpad analytics — every DBC config aggregated: launches, graduations, volume, fees.
  • Curve explorer — any config's liquidity curve sampled with the official SDK math (price vs. quote raised).
  • Ticker spoof detection — symbols hiding bidi / zero-width characters (e.g. U+202E) are cleaned and flagged.

Streaming

Server-Sent Events

GET /api/stream?types=…&pool=… — filters are optional and comma-separated. Supports Last-Event-ID for gap-free reconnects.

const es = new EventSource('/api/stream?types=graduated,migrated,whale');
es.addEventListener('graduated', (m) => console.log(JSON.parse(m.data)));
es.addEventListener('swap', (m) => console.log('whale', JSON.parse(m.data)));

WebSocket

WS /ws — send a subscription, receive JSON events.

const ws = new WebSocket('wss://your-host/ws');
ws.onopen = () => ws.send(JSON.stringify({ op: 'subscribe', types: ['pool_created', 'near_graduation'], pools: [] }));
ws.onmessage = (m) => console.log(JSON.parse(m.data));

Event types

typeWhenKey fields
swapEvery buy/sell on a DBC curveside, trader, baseAmount, quoteAmount, usd, priceUsd, mcapUsd, progress, flags[whale|sniper|dev]
pool_createdEvtInitializePoolpool, mint, creator, config, migrationTarget
near_graduationProgress first crosses NEAR_GRAD_PCT (80%)progress, etaSec, mcapUsd
graduatedEvtCurveCompletequoteReserve, timeToGraduateSec, mcapUsd
migratedmigration_damm_v2 / migrate_meteora_dammdammPool, target

whale and sniper can also be used as stream filters (they match flagged swaps).

TypeScript client

packages/client — zero dependencies, works in browsers and Node ≥ 18 (SSE parsed over fetch, auto-reconnect with resume).

import { DbcFlow } from 'dbc-flow-client';
const flow = new DbcFlow({ baseUrl: 'https://your-dbc-flow.app' });

const near = await flow.nearGraduation(85);          // pools ≥ 85% of their curve
const lps  = await flow.launchpads({ sort: 'graduated' });
const curve = await flow.curve(near[0].config);        // price vs. quote raised

for await (const ev of flow.stream({ types: ['graduated', 'migrated'] })) {
  console.log(ev.symbol, ev.type, ev.dammPool ?? '');
}

const stop = flow.on('whale', (ev) => console.log('🐋', ev.symbol, ev.usd));

MCP server (AI agents)

packages/mcp exposes 6 tools — dbc_near_graduation, dbc_hot_pools, dbc_pool, dbc_launchpads, dbc_curve, dbc_recent_events — so an agent can answer “which DBC launches are about to graduate and who is sniping them?”.

claude mcp add dbc-flow -e DBC_FLOW_URL=https://your-dbc-flow.app -- node packages/mcp/index.js

Self-host

git clone <repo> && cd dbc-flow && npm i
echo "HELIUS_API_KEY=..." > .env
npm start            # http://localhost:4100

Ingestion modes: INGEST_MODE=batch (default — Helius getTransactionsForAddress, up to 100 full transactions per call, ~100% coverage, ordered processing) or INGEST_MODE=single (any Solana RPC: logsSubscribe + rate-limited getTransaction with a priority queue that never drops launches / migrations).
